Asking who is ready

Pick exactly one of these and use it for everything. They all answer the same question — which of my descriptors can I touch right now without blocking — and differ only in how they scale and where they exist.

poll<poll.h>
int poll(struct pollfd *fds, nfds_t nfds, int timeout);
does
You hand it an array of {fd, events, revents}. It sleeps until at least one fd is ready, fills in revents, and returns how many are ready.
here
The default choice: portable across Linux and macOS, no fd-number ceiling, and one array you rebuild or maintain each loop. Set events to POLLIN, POLLOUT, or both — the subject requires watching read and write simultaneously.
watch
Also check POLLHUP and POLLERR in revents: the client vanished, and that connection has to be cleaned up from whatever state it was in.
select<sys/select.h>
int select(int nfds, fd_set *r, fd_set *w, fd_set *e, struct timeval *timeout);
does
The oldest of the four. Same question, answered with bitmasks instead of an array.
here
Works, and the evaluation sheet is written in its vocabulary. FD_SET, FD_CLR, FD_ISSET, FD_ZERO are explicitly allowed.
watch
Hard-capped at FD_SETSIZE (usually 1024) and it rewrites your fd_sets every call, so they must be rebuilt from scratch each loop.
epoll_create / epoll_ctl / epoll_wait<sys/epoll.h>
int epoll_create(int size); int epoll_ctl(int epfd, int op, int fd, struct epoll_event *ev); int epoll_wait(int epfd, struct epoll_event *evs, int maxevents, int timeout);
does
Linux's scalable version. You register interest once with epoll_ctl and the kernel keeps the set, so each wait costs nothing per idle connection.
here
Faster at high connection counts and genuinely nicer to use — but it exists only on Linux.
watch
Breaks your three-target rule. Your MacBook has no epoll, so an epoll-only server will not build there. Choosing epoll means writing a kqueue path too.
kqueue / kevent<sys/event.h>
int kqueue(void); int kevent(int kq, const struct kevent *cl, int nc, struct kevent *el, int ne, const struct timespec *t);
does
The BSD and macOS equivalent of epoll.
here
The other half of the portability problem, if you go down that road.
watch
Does not exist on Linux, so this one will not build on your desktop or at 42.

Anything you learn about these — a man-page detail that bit you, a flag you had to look up, a snippet that finally worked — belongs in this file, next to the function it explains.
