Running a CGI

fork is banned in this project for everything except CGI. These five calls are the whole of that exception.

fork<unistd.h>
pid_t fork(void);
does
Duplicates the calling process. Returns 0 in the child and the child's pid in the parent.
here
Called once per CGI request, after the pipes exist. The child rewires its descriptors and execs the interpreter; the parent goes straight back to its poll loop.
watch
The parent must never wait for the child in a way that blocks the loop. Every other client keeps being served while the script runs.
execve<unistd.h>
int execve(const char *path, char *const argv[], char *const envp[]);
does
Replaces the current process image with a new program. On success it does not return — there is no "after".
here
This is where REQUEST_METHOD, QUERY_STRING, CONTENT_LENGTH and the rest reach the script: you build envp yourself and pass it here.
watch
Both argv and envp must be NULL-terminated arrays of C strings. Building those from std::string in C++98, and freeing them, is fiddly — write it once, carefully.
waitpid<sys/wait.h>
pid_t waitpid(pid_t pid, int *status, int options);
does
Collects a finished child and its exit status.
here
Call it with WNOHANG so it returns immediately whether or not the child has finished. Poll the pipe for output; reap the child when it is done.
watch
Without WNOHANG you block your entire server on the CGI script — which is precisely the infinite-loop trap. Never reaping leaves zombie processes.
kill<signal.h>
int kill(pid_t pid, int sig);
does
Sends a signal to a process.
here
Your timeout enforcement: a CGI child that has run too long gets SIGKILL, and the client gets 504 Gateway Timeout. Then waitpid to reap it.
watch
Somebody has to decide "too long". If nobody does, an infinite-loop script hangs that connection forever and the evaluator finds it.
signal<csignal>
void (*signal(int signum, void (*handler)(int)))(int);
does
Installs a handler for a signal.
here
One line that matters: signal(SIGPIPE, SIG_IGN). Otherwise writing to a socket the client already closed kills your whole process — an instant zero.
watch
Do that at startup, before the loop. It is one of the cheapest crash-proofings in the project.

Anything you learn about these — a man-page detail that bit you, a flag you had to look up, a snippet that finally worked — belongs in this file, next to the function it explains.
