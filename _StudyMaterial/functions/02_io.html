allowed functions — group 02

Moving bytes

Four calls that read and write, and two that end a conversation. Every one of them may do less than you asked — that is the normal case, not an error.

recv<sys/socket.h>
ssize_t recv(int fd, void *buf, size_t len, int flags);
does
Reads up to len bytes from a socket into your buffer. Returns how many it actually read.
here
Called only when poll() says the fd is readable. Append what you get to that connection's read buffer, then ask whether a complete request is in there yet.
watch
Three return values, three meanings. > 0 = that many bytes. 0 = the client closed the connection — clean up. -1 = error, drop the client. Checking only one of them is called out explicitly in the evaluation sheet.
send<sys/socket.h>
ssize_t send(int fd, const void *buf, size_t len, int flags);
does
Writes up to len bytes to a socket. Returns how many it actually took.
here
Called only when poll() says writable. It may take 4 KB of your 2 MB response, so you store the offset and continue on the next writable event.
watch
Assuming send wrote everything is the bug that makes small files work and large files corrupt. The return value is the whole point of the call.
read<unistd.h>
ssize_t read(int fd, void *buf, size_t count);
does
The generic version of recv, for any descriptor.
here
Use it for regular files (the static file you are serving) and for the CGI output pipe. Subject v24.1 exempts regular disk files from needing poll first — sockets and pipes are never exempt.
write<unistd.h>
ssize_t write(int fd, const void *buf, size_t count);
does
The generic version of send.
here
Writing an uploaded file to disk, and pushing a request body into the CGI's stdin pipe.
watch
Same partial-write rule as send when the target is a pipe.
close<unistd.h>
int close(int fd);
does
Releases a descriptor. When the last reference to a socket goes, the connection is torn down.
here
Every accept must eventually be matched by a close, every open too, and both ends of every CGI pipe.
watch
Leaked fds are a slow death: the server works fine, then stops accepting anyone once it hits the per-process limit. A siege run will find this.
shutdown<sys/socket.h>
int shutdown(int fd, int how);
does
Closes one direction of a connection while leaving the other open.
here
Rarely needed here. close is what you normally want.

Anything you learn about these — a man-page detail that bit you, a flag you had to look up, a snippet that finally worked — belongs in this file, next to the function it explains.
