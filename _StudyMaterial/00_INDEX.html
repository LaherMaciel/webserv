the mapTen topics, in the order they make sense

Each one is a separate file in topics/, so it can grow without dragging the others with it. Read top to bottom the first time — every topic assumes the one before it.

  • 01 What you are actually building One socket listens, every client gets its own. Why accept() hands you a new descriptor, and what a server actually is.
  • 02 The bytes A real request and a real response, annotated line by line. \r\n, the blank line, and the promise Content-Length makes.
  • 03 When does a message end? The three framing answers — no body, Content-Length, chunked. Answer this and the parser designs itself.
  • 04 Why poll() exists Blocking versus readiness, drawn side by side. One silent client must not freeze the other ninety-nine.
  • 05 The connection state machine The centrepiece. Partial reads, partial writes, keep-alive, hangup — six boxes that replace a thousand special cases.
  • 06 From URL to file Port and Host pick the server block, longest prefix picks the route, and the root replaces the matched prefix.
  • 07 CGI Environment variables, two pipes, fork and execve. What every web framework was built on top of.
  • 08 Where the work splits in two Moving bytes versus deciding what they mean, meeting at a Request and a Response. The conversation to have with Beth.
  • 09 The hard zeros The rules that end an evaluation on the spot — and why most of them are architecture, not detail.
  • 10 Check yourself Seven questions to answer out loud, without notes, before the kickoff.
  • 11 The allowed functions → Once the ten topics make sense and you can answer the questions, this is the other half of the map: all 39 external functions the subject permits, grouped by job — what each one does, and what it does to you if you get it wrong. a separate reference · 8 groups · read it by lookup, not front to back

how this folder worksWhere things go

One topic, one file. When you find a video, an article, or a paragraph worth keeping, it goes in that topic's file — not in a general pile. Six months from now the question "where did I read that thing about chunked bodies?" has exactly one answer.

When a topic outgrows its file, it splits: a deep dive on poll() becomes topics/04a_poll-internals.html, sitting next to its parent. The numbering keeps the reading order visible in the file listing itself.

LINKS.md is the running source list — every URL used on this project, added as it's found, so nothing has to be re-found later.

The README is the destination, not this folder. This is the workshop: rough, growing, and allowed to be wrong. What survives gets rewritten into the README in your own words — the way NetPractice's did.
